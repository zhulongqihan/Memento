# 几度 · Memento 四季视觉系统交接入口

这是一套面向后续设计与实现窗口的自包含交接包。接手者不应依赖此前聊天记录，也不应根据图片自行补造功能。

## 必读顺序

1. `../../PRODUCT.md`：确认产品目标与功能边界。
2. `../../DESIGN.md`：确认全局视觉原则。
3. `four-seasons-visual-narratives.md`：理解四季 × 三种视觉叙事的设计决策。
4. `visual-implementation-spec.md`：按精确布局、token、状态和响应规则实现。
5. `asset-manifest.md`：理解每张参考图的用途、可借用内容和禁止照抄内容。
6. `LUNA-HANDOFF.md`：作为交给 GPT-5.6 Luna 的完整实施任务书。

## 事实优先级

当文档、图片和当前代码存在差异时，遵循以下优先级：

1. 用户真实数据与现有功能不能丢失。
2. `PRODUCT.md`、`DESIGN.md` 和本目录的书面规范。
3. 当前代码中已经通过测试的数据、备份与交互逻辑。
4. 生成的视觉参考图。

**书面规范始终高于图片。** 视觉参考图只定义构图、比例、光线、密度和气质。图中的文字、日期、统计值、设置项、路径、图标和照片内容均可能是生成模型的临时内容，不得直接视为产品需求。

## 已确认的产品决策

- 四个主 Tab 名称与顺序不变：此刻、时光、几度、我的。
- 固定季节映射：春·此刻、夏·时光、秋·几度、冬·我的。
- 新增三种可切换视觉叙事：典藏、光影、刻度。
- 默认视觉叙事：典藏。
- 视觉叙事与现有浅色、深色、高对比模式独立。
- 不按真实月份自动换季，不允许为单个 Tab 单独选叙事。
- 切换视觉叙事不改变记录、照片、筛选、滚动、子 Tab、备份或表单数据。

## 实现原则

- 建立一套共享语义结构，再用布局与 token 表达三种叙事；不要复制三套业务组件。
- 四季是页面身份，视觉叙事是观看方式，浅色／深色／高对比是阅读条件，三者不能混为一个枚举。
- 生成图里的大片摄影只用于需要摄影的内容槽位，不得把用户内容区变成背景海报。
- 所有交互保持产品级熟悉感：标准 Tab、按钮、单选、下拉、表单、抽屉与对话框。
- 不增加图片中偶然出现但产品不存在的功能，例如天气、地理坐标、设备参数、光盘归档、打印系统或自动人生分析。

## 开工前检查

- 先查看 `git status` 和 `git diff`，保护其他窗口正在进行的 `src/App.tsx` 与 `src/styles.css` 修改。
- 找到现有四页、设置偏好、迁移和备份的完整调用链后再改。
- 先实现设置字段、根属性和共享 token，再实现页面差异。
- 每完成一种叙事，先跑现有测试并检查备份兼容，再进入下一种。

## 交付必须包含

- 三种视觉叙事的四个主页面，共 12 个可工作的页面状态。
- 设置页中可键盘操作、即时生效、可持久化的视觉叙事切换器。
- 浅色、深色、高对比、舒适、紧凑、reduced motion 的组合验证。
- 1280×720、1440×900、1920×1080 截图；1440×900 为主验收画面。
- 空数据、无照片、大量记录、损坏图片、存储失败与旧备份迁移验证。
- Windows 安装包、校验值、发布说明与 `docs/reviews/` 审阅记录。

## 明确禁止

- 蓝紫渐变、玻璃拟态、Bento Dashboard、大面积阴影、过度圆角。
- 用花朵、太阳、落叶、雪花贴纸代替季节设计。
- 把数字做成 KPI 卡片阵列。
- 为了主题切换复制数据状态或业务逻辑。
- 在主题切换时刷新应用、丢失滚动或关闭未完成表单。
- 将生成图中的错字、虚构内容或额外功能带入产品。
