# 几度 · Memento 发布路线

当前发布策略是两个大版本、十个小版本。每个正式版本都必须生成 Windows x64 NSIS `.exe`，并在发布后完成自我审阅。

## 版本清单

| 版本 | 主题 | 主要验收 |
| --- | --- | --- |
| v1.0.0 | 首个桌面 MVP | 四页、Moment、经年、余下、刻度、本地保存、基础备份、安装包 |
| v1.1.0 | Moment 与照片 | 编辑、照片预览、详情页、删除清理 |
| v1.2.0 | 时光档案 | 年月分组、类型筛选、置顶和定位保持 |
| v1.3.0 | 经年体验 | 多种时间显示、排序、置顶和边界修复 |
| v1.4.0 | 余下体验 | 真实日期列表、周五/周六/周日/周末边界 |
| v1.5.0 | 第一代稳定性 | 可访问性、错误状态、性能和安装流程 |
| v2.0.0 | 正式桌面版 | schema v2、数据迁移、恢复快照、照片索引稳定性 |
| v2.1.0 | 分享卡片 | 本地生成 Moment、经年、余下 PNG 卡片 |
| v2.2.0 | 确定性时间单位 | 自定义星期、用户配置工作日 |
| v2.3.0 | 刻度深化 | 多阶段管理、阶段详情、可选人生进度 |
| v2.4.0 | 显示与主题 | 深色、高对比度、数字和密度偏好 |
| v2.5.0 | 安全备份 | 加密备份、完整性校验、发布流程固化 |

## 每轮发布门禁

1. 功能分支完成并提交 Pull Request。
2. `npm run typecheck`、`npm test`、`npm run build` 通过。
3. Windows `npm run tauri:build` 通过。
4. 安装包在至少一台 Windows 环境中启动冒烟通过。
5. 检查数据保存、导出、导入和旧版本兼容性。
6. 检查 1280px、1440px、1920px 桌面布局。
7. 发布 GitHub Release 和 SHA-256。
8. 发布后新增 `docs/reviews/vX.Y.Z.md`，记录成功、不足、风险和下一轮修复项。

## 问题等级

- P0：数据丢失、无法启动、安装包损坏，阻止发布。
- P1：核心记录、计算、导入流程错误，下一版本前必须修复。
- P2：明显体验缺陷，可以进入下一轮。
- P3：低优先级优化，进入长期清单。
