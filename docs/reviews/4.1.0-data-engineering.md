## 结论

在本次检查范围内，**未发现可复现的新增 P0、P1 或 P2 问题**。原单次日期语义问题已经在领域显示函数及其生产消费者中一致修正；没有发现新单位漏入持久化格式、日期被改写、照片关联被静默删除或私人测试数据进入 CI 上传范围。

以上为独立源码与数据契约审阅结论，不是正式发布放行。审阅者没有重跑测试；下方的最终运行证据由主流程于 CI 完成后补充，明确区分来源。

## 核对结果

- **自然日保存格式兼容。** `recording-overlays.tsx` 的 `calendar` 只存在于局部 `RemainingSelection`；提交前转换成 `unit: custom` 与 `[0,1,2,3,4,5,6]`。`App.tsx` 沿用现有余下保存分支；`RemainingUnit`、schema 4 与迁移校验器均未扩展。旧的全星期自定义记录打开时显示自然日，其底层类型仍被旧格式接受。
- **计算与状态边界明确。** `getRemainingDisplay` 对自然日按日期差区分未来、今天、过去，并且不生成中间日期；对星期计数保留不含今天、包含截止日的规则。未来没有匹配星期、今天截止、截止已过分别输出不同说明。全七天的识别不依赖顺序或重复值，函数不修改原数组。测试源码覆盖上述边界及跨闰日、跨年、数字分组。
- **生产显示使用同一语义。** 几度主读数、余下列表、此刻摘要、漂流摘要与余下分享卡均使用 `getRemainingDisplay`。分享卡保存实际目标日期和对应说明，不再取匹配日列表的第一天作为事件日期。生产 TS/TSX 搜索未发现旧“下一次”“个自定义日”或详情硬编码序号语句。
- **持久化与恢复路径未变。** `repository.ts`、`sqlite-database.ts`、`backup.ts`、`backup-import.ts`、`migration.ts`、`merge.ts`、资产存储和 Rust 数据实现没有本轮差异。`src/data` 的变化仅为分享卡展示结构，不是记录格式变更。
- **照片保护仍成立。** 无图详情仅收起没有引用时的照片区域；有引用但缺失的照片继续逐项显示占位。记录编辑仍通过 `resolveMomentPhotoIds` 合并原引用，并只移除用户明确选择的 ID；本轮未更改此函数或保存分支。
- **发布与私人数据隔离。** 构建和产物路径按 package 版本派生。Windows Candidate 上传白名单仅为当前版本发布目录、`output/playwright/release-<version>/` 和 `output/native-verification/`；版本解析失败时不进入上传步骤。`verify-reading.mjs` 使用代码内生成的合成记录，不读取桌面表格或私人体验副本。原生脚本保留只允许 disposable GitHub hosted Windows runner 的限制。
