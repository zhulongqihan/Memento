# 4.0.0 数据安全审阅

更新时间：2026-10-23 18:04 +08:00。结论：照片编辑引用缺陷已修复并通过浏览器回归；正式 Windows 产物的原生验收 P1 仍开。

## 根因与修复

异常照片编辑原先把可显示照片列表当作完整引用集合，导致只改文字也丢关联。现在保存合并原始 ID 与新照片，仅按显式移除列表删除；缺失/损坏图有占位。单元测试通过真实资产层与 repository 保存/重载，生产 UI 回归也确认原关联保留。

浏览器不同 ID 同时写入曾跨异步边界持有旧索引，最后一次覆盖前次结果。现两处提交都在同步读写间合并最新索引，屏障测试和三图 UI 回归通过。结论限同一页面执行环境，不代表多标签页事务。

## 已验证边界

- 不再按固定示例 ID 删除记录。
- v4 状态只存照片 ID；备份不含运行时 Blob URL。
- 迁移先验证资产、写 recovery，再提交 current；日志保留真实来源 schema。
- Tauri 文件写入不覆盖已有文件；导入失败只回滚该操作新增资产。
- 浏览器缺失/损坏照片警示、合并失败重试、替换后恢复、恢复后清理独占资产均通过。
- 合成旧版加密 fixture 根据实际 3.1.0 envelope 生成，验证格式兼容，不是用户生产备份样本。
- 65 项前端、2 项 Rust 测试通过；此前隔离 test feature 已通过 SQLite 故障/重试，但不替代正式路径。

## 正式产物 P1

[独立 Windows CI](https://github.com/zhulongqihan/Memento/actions/runs/39935987568) 使用实际 Known Folder、全新应用目录、正式 exe 和合成数据。需完成旧表结构初始化、真实 3.1.0 程序、迁移失败保留及重试、原生坏图编辑、替换恢复、卸载保留数据后，才能关闭交付 P1。

历史一次只设置 APPDATA 的 portable 启动可能访问真实用户数据库，影响未知。之后不再读写、迁移或恢复真实数据库；新 VM 验收无法反证历史影响。此前注册表重定向在执行前被工具策略拒绝，没有该写入，也不换方式绕过。

证据入口：`output/playwright/v4-completion/verification.json`；原生报告尚待生成。详细历史诊断见 [历史审阅](https://github.com/zhulongqihan/Memento/blob/abef939e0b09da9e7efe4ef971663703d6d3a482/docs/reviews/4.0.0-data-safety.md)。
