# v2.0.0 发布后自我审阅

状态：已完成版本审阅；第二个大版本完成 schema v2、迁移和恢复快照，本地 Windows 安装包已构建并通过启动冒烟，代码已纳入最终版本链。

## 本轮完成

- `AppState.schemaVersion` 升级为 v2。
- 旧的 v1 本地状态会在读取时迁移到 v2，并补齐 v1.2/v1.3 新增的显示偏好。
- 浏览器存储从 `memento:app-state:v1` 迁移到 v2 key，同时保留读取旧 key 的兼容路径。
- SQLite 继续使用同一张状态表，旧 payload 读取后自动升级并由后续保存写回 v2。
- 替换导入前自动写入恢复快照，恢复快照同时支持浏览器本地存储和 Tauri SQLite。
- 我的页显示恢复入口，恢复成功后删除快照，避免反复误恢复旧数据。
- 旧 v1 JSON/ZIP 备份导入时先迁移再进入合并/替换流程。
- 增加 schema 迁移测试，覆盖旧设置补齐和未知数据拒绝。

## 已验证

- `npm run typecheck` 通过。
- `npm test -- --run` 通过，4 个测试文件、15 个测试全部通过。
- Playwright 真实流程验证：导入 v1 备份、替换本机数据、看到恢复入口、恢复后回到原有 3 条 Moment 且恢复入口消失。
- `npm run tauri:build` 通过；`memento.exe` 启动 3 秒后进程保持运行且窗口响应正常。

## 仍然存在的不足

1. 恢复快照只保留最近一次替换前状态，不支持多版本历史。
2. SQLite 和浏览器 fallback 的存储层还没有统一的迁移日志或版本诊断页。
3. v2 仍以内嵌 Data URL 保存照片，照片索引/资源文件化留给后续版本。
4. 尚未完成干净 Windows 环境安装、覆盖升级和卸载实测。
5. GitHub 当前令牌仍没有创建 PR/Release 的权限。

- P2：多快照历史、迁移诊断、照片资源文件化。
