# v2.5.0 发布后自我审阅

## 版本目标

完成两大版本、十个小版本的约定。本轮把备份从“可导出”推进到“可验证、可加密、可拒绝错误输入”，并固化最终 Windows `.exe` 交付信息。

## 已完成

- 新增 `.memento` 加密备份格式：PBKDF2（SHA-256，210,000 次迭代）派生 256 位 AES-GCM 密钥。
- 每次加密备份使用新的随机 salt 和 IV；密码不写入应用状态，也不写入备份文件。
- 加密备份解密失败、密码错误、容器损坏和认证标签不匹配时统一拒绝，数据不会进入合并/替换流程。
- 普通 JSON 和 ZIP 备份的 manifest 增加 SHA-256 摘要，导入时先校验原始数据，再迁移 schema。
- 设置页增加密码输入、加密导出和 `.memento` 导入入口；密码少于 8 个字符时按钮保持禁用。
- 旧 JSON/ZIP 仍可导入；没有完整性摘要的历史备份继续按兼容模式读取。
- 发布检查清单加入加密备份、错误密码和篡改文件验收项。

## 不足与风险

- P0/P1：当前没有发现会阻止本轮交付的数据丢失、错误解密或启动问题。
- P1：本机已完成构建和真实浏览器验收，但仍未获得独立干净 Windows 环境完成安装、覆盖升级、卸载闭环。
- P1：用户忘记加密密码后无法恢复内容；产品必须在导出时明确提示用户自行保管密码，本轮已在成功提示中说明。
- P2：历史 JSON/ZIP 如果没有 `integritySha256` 字段，只能依靠旧有格式校验，无法追溯其导出后的篡改。
- P2：`.memento` 当前是 JSON 容器，照片和大数据集会增加文件体积；下一阶段可考虑压缩后再加密。
- P3：GitHub 当前 CLI Token 仍缺少创建 PR 的权限；Release 已通过仓库 GitHub Actions 的 `GITHUB_TOKEN` 创建并上传 Windows 便携版与安装包。

## 十轮迭代结论

v1.1–v1.5 完成记录、照片、时光档案、经年/余下计算和第一代稳定性；v2.0–v2.5 完成正式桌面数据迁移、分享卡片、自定义星期、阶段/人生进度、显示主题和安全备份。当前版本已经满足“Windows 便携版直接打开、本地优先、可持续记录、可迁移和可验证”的第一阶段目标。

后续若继续发展，优先级应转向独立安装升级验收、响应式小窗口、多语言和压缩加密备份，而不是继续堆叠记录类型。
