# 4.2.0 数据与工程复核

日期：2026-11-05。范围为 4.2 相对 4.1 的功能改动，以及这些改动实际调用的保存、导出和恢复路径。此文记录源码与隔离浏览器复核；候选安装包、Windows 原生与 CI 的最终结果应另见版本验收记录。

## 结论

在本次检查的调用链中，编辑身份、草稿退出保护、每日记录日期及删除语义的修复成立。复核额外发现一个普通备份失败时缺少用户反馈的问题，已补齐处理和回归。本轮未改 schema v4、数据库结构、资产存储格式或加密格式；不以此前 4.1 的原生验收代替 4.2 验收。

## 调用链与行为

| 检查项 | 核对结果 |
| --- | --- |
| 编辑身份 | `App.changeRecorderType` 对当前类型或已有编辑记录不再清除身份；记录抽屉编辑期间禁用其他类型。保存仍使用已有 ID，保留原创建时间。 |
| 未保存记录 | 抽屉比较初始字段及照片引用快照，关闭、背景、Esc 和新建时切换类型统一确认。改回初始值后可直接关闭；取消放弃后保留输入与抽屉内焦点。照片新增和移除纳入检查，卸载仍撤销草稿对象 URL。 |
| 跨日 | App 的本地日于午夜、窗口恢复焦点和页面可见时更新；今日旁白和已保存一行使用这一日期。每日草稿另绑定开始编辑的日期，跨日后显示具体日期并保存回原日。 |
| 每日删除 | 首页与历史页共用一次确认；取消不改状态。空文本保存只提示补写，不再隐式删除已有一行。 |
| 时光查找 | 查询和视图位于 App 会话状态，切页卸载不会清除；清空时间册会重置。没有向持久化 schema 添加字段。 |
| 人生年限 | 输入草稿与已保存值分开，离焦或 Enter 仅接受 1–150 整数；非法输入显示错误并保留原已保存值。 |
| 备份内容文案 | JSON、ZIP 与加密导出均调用 `backup.ts/buildPayload`，保存完整业务状态、设置和被记录引用的照片。JSON 将照片字节编码为 base64，ZIP 将相同字节保存为独立资产文件，加密格式包裹相同 payload。“相同内容”指业务及照片内容，不指相同封装字节。 |
| 备份完整性 | 构建 payload 前读取资产并核对长度与 SHA-256；缺少索引、文件或摘要不符时继续拒绝导出，不生成缺图的“完整备份”。修复没有放宽此拦截。 |
| 替换与清空 | 仍先写 recovery 快照；备份导入继续使用 staged transaction 和失败回滚。设置页的分组及按钮层级变化没有绕开原有确认和恢复路径。 |

## 额外发现与修复

**P2：普通备份导出失败时页面没有结果。** 设置页 JSON 与 ZIP 原回调直接丢弃 Promise，而加密导出已有异常处理。用新的浏览器上下文创建一个引用缺失照片的合成记录，点击 JSON 和 ZIP 后各产生一次未捕获异常，页面没有提示；同一状态加密导出可以显示失败原因。

已在 App 增加普通导出的统一异步包装：等待完成后提示生成成功，失败时显示数据层返回的具体原因。保留底层完整性检查。新增流程验证每种格式必须分别出现失败提示、不得触发下载、不得产生浏览器未捕获错误，且前后持久化状态和照片引用保持一致。

另修正状态流程脚本的归档位置：从固定诊断目录改为 `output/playwright/release-${version}/state-flows/`，使 Windows 候选 artifact 能包含这组证据。历史诊断文件未移动或删除。
